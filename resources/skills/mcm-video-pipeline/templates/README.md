## 二、决策树

```
问：内容能不能用「编号 + 一句话」表达？
├─ 能，且总条数 ≤ 10
│   ├─ 是紧迫场景（考前 / 开赛前 / 截止前）→ T2 大字清单档
│   └─ 不是紧迫场景 → T2 也行，但优先看下面
└─ 不能（需要对比、推导、多版式）
    ├─ 主体是「一道真题的完整求解过程」→ T3 真题长拆解档
    ├─ 主体是「论文里的图 / 题目原图」逐张讲 → T4 奶油论文图解档
    ├─ 主体是「赛事资讯」→ T5 赛事资讯快报档
    ├─ 核心是「数字」而不是「句子」→ T8 数据仪表盘档
    ├─ 核心是「一句话主张」而不是一堆信息 → T9 杂志排版档
    ├─ 内容是「规定 / 细则 / 红线」，有官方分量 → T10 黑金权威档
    ├─ 内容像「我记在笔记本上的一页」→ T7 纸感笔记档
    ├─ 内容是「N 个坑 / N 条规则」并列清单，且要**工程极轻**（不想装依赖 / 要交付可双击打开的源码）→ **T11 单文件 HTML 档**
    └─ 其余（方法对比 / 对错辨析 / 评分细则 / 自查清单）→ T1 信息密度档
```

**时长校验**：
- < 2 分钟 → T2（其他档撑不到那么短）
- 2–3 分钟 → T5 / T7 / T8 / T9 / T10 / **T11**，或 T1 压到 185s
- 3–4 分钟 → T4
- 4–6 分钟 → T3

**一句话记忆**：
**能不能用「编号 + 一句话」表达？能 → T2；不能 → T1。**
真题 → T3，图讲解 → T4，资讯 → T5，数字 → T8，主张 → T9，规定 → T10，笔记 → T7，**要轻 → T11**。

## 四、混搭规则

用户说「T1 的配色 + T5 的版式」这类混搭时，**先确认三件事**：

1. **时长**：以版式多的那档为准（T5 的 10 版式撑不到 120s，会变成 180–200s）
2. **配色来源**：从哪档拿 `theme.ts`，另一档的 accent 语义色要重新映射
   - T1/T5 是 8 色 accent，T2 是 3 档语气，T7/T8/T9/T10 各有固定语义色
   - 映射关系要先写出来给用户看
3. **字幕模式**：混搭时只能选一种（句级 / 整段），不能一个视频里两种并存

**浅色档和深色档不要混**。T4 / T7 / T9 是浅色底，T1 / T2 / T3 / T5 / T8 / T10 是深色底，中途换底色会让观众觉得换了个视频。

混搭后要重新算字数预算，并明确告诉用户「这是第一次跑这个组合，版式间距可能需要一轮微调」。

## 六、`templates/code/` 说明

### 6.1 Remotion 组件（T7–T10）

放 T7–T10 的**可运行 Remotion 组件源码**。每套有**两个形态**：

| 形态 | 文件 | 用途 |
|---|---|---|
| 单页演示 | `T7PaperNote.tsx` | 看这套风格的一个页面长什么样 |
| **完整视频组件** | `T7PaperNoteVideo.tsx` | **读 `timing.json`，按帧切场景 + 句级字幕，真能出片** |

外加一个四套共用的**场景引擎** `src/remotion/shared/`：

- `types.ts` — `TimingData` / `Section` / `Sentence`，与 `_gen_tts.py` 产出的结构一一对应
- `scene.ts` — `useScene()` 按帧定位场景，返回场景内归一化进度 `p`
- `Subtitle.tsx` — 句级实时刻**硬切**字幕条（不加淡入，与音频轨逐词对齐）

### 关键设计：动画基于场景内局部帧

```tsx
const { frame, sec, section, p } = useScene(timingData);
const lf = frame - section.start_frame;   // ← 所有动画用 lf，不用绝对帧
```

这样改某个场景的时长，动画节奏不用跟着改。这是 `references/pipeline.md` 里「动效三条铁律」第 3 条的落地。

### 演示数据

`videos/demo/timing.json` —— 5 场景 / 32.75s / 982 帧，主题「灵敏度分析三步」，句级时刻齐全。
换期时把 `demoData.ts` 换成你的场景内容，`timing.json` 由 `_gen_tts.py` 生成（**不要手改**）。
